# Particle collision contract

`ParticleEmitter` can leave collision off (the default), kill particles on contact, or bounce them. `collisionBounce` is restitution from 0 to 1; `collisionFriction` removes that fraction of tangential velocity. `collisionMask` is passed to the scene physics ray query. Triggers and the emitter's own collider are ignored. Collision uses a swept line from each particle's previous position to its solver-updated position once per 60 Hz step. Particle size is visual only: the contact path has zero radius, so thin or fast-moving geometry can still be missed when the collider moves across a stationary particle.

Scripts can read `GetCollisionHits()` after the emitter updates. Each entry contains the stable particle ID, non-owning collider object pointer, world contact point and normal, incoming and outgoing world velocities, simulation tick, and kill flag. Hits from all fixed steps in one `Advance` are ordered by step and particle storage order. The next `Advance`, `Reset`, or scene reload replaces the batch. A batch holds up to 4096 hits; `GetDroppedCollisionHitCount()` reports overflow. No scene object is created for a particle. A script should copy data it needs before the collider object is deleted.

The ray uses the collider pose currently held by scene physics. Bounce subtracts the collider's current linear velocity before calculating restitution and friction, then adds it back. Moving collider motion is not swept against stationary particles, and rotating surface velocity is not yet sampled. Local-space particles are converted to world space for the query and response, then converted back using the emitter's current transform. A singular emitter transform skips collision for that step.

Particles do not traverse portals in this stage. Their simulation positions and velocities stay in the source world chart (or emitter-local coordinates). Straight collision rays do not follow connected portal paths; aperture rims can be hit as static colliders, while remote split-piece proxies are ignored. Portal rendering can still show the particles through a portal. True particle traversal needs a later step that maps both position and velocity through an aperture, switches chart ownership, and queries the destination collider scope.
