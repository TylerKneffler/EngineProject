# Skinned soft tissue, layered surfaces, and subsurface scattering

Research and code audit: 2026-10-12. This is a requirements proposal, not an implemented feature.

## Meaning and scope

The original stretch/compression item concerns **shape**: a skinned surface should respond locally to joint motion and collision impulses, then settle back toward its current animated pose. Subsurface scattering (SSS) concerns **appearance**: light enters the surface, travels within tissue, and exits nearby. Layered meshes are a possible way to model physical skin sliding over muscle/fat; layered optical parameters can approximate light transport without adding geometry. Keep these systems independently switchable so a stylized creature can use deformation without skin shading, and a static translucent mesh can use SSS without a skeleton.

The first shipping target should be a bounded surface response on the existing skinned mesh. A separate low-resolution flesh proxy and skin shell should follow only if the visible requirement is skin sliding, fat volume, or contact between tissue layers. Pixar's skin simulation describes anchors on a moving underlying mesh and notes that naive closest-point attachment can snag in folds; a full layered simulation therefore carries substantial binding and self-contact work. [Pixar skin simulation](https://graphics.pixar.com/library/SkinForIncredibles2/paper.pdf). Blender's surface deformation documentation likewise describes binding a high-detail surface to a lower-detail driver and warns about invalid or distant target geometry. [Blender Surface Deform](https://docs.blender.org/manual/en/4.4/modeling/modifiers/deform/surface_deform.html).

## Engine facts that shape the design

- `SkinnedMesh::BuildPalette()` resolves the active skeleton in mesh-local space. `Object.hlsl::VSMain` currently applies morphs, then linear blend skinning, then object transform. The CPU triangle stream in `Mesh::BuildPortalCutTriangleStream()` duplicates that order for contacts and portal cuts.
- `MeshObjectCollider::Contact` already exposes a stable-ish contact ID, summed impulse across physics substeps, world contact point/normal, mapped surface triangle and barycentric coordinates, and nearby bone weights. Mapping can fail when a convex hull is too far from the visible surface, so only `surfaceMapped` contacts should drive local dents.
- `Skeleton::ApplyMeshContactResponse()` already consumes those contacts for bone torque and secondary bone motion. A surface response must share the event without applying a second rigid-body impulse.
- `Scene::Update()` runs component updates before the physics step. Bullet publishes contacts and applies skeleton contact response during the physics step. Soft-tissue evaluation needs a post-physics hook or a documented one-frame latency; the former is preferable for contacts and final bone pose.
- `Mesh::SetDeformedVertices()` replaces the current vertex stream, clears indices, and marks configuration dirty. It is suitable for procedural cut/cloth paths, but should not be called every frame for a skinned surface. Keep authored geometry, skin weights, UVs, morph targets, and topology immutable; add transient deformation state.
- The current object shader is a forward PBR shader with base color, metallic/roughness, normal, occlusion, emissive, and height inputs. It has no SSS parameters, thickness input, material mask, or lighting buffer specifically for diffuse scattering.

## Required: bounded skinned surface response

1. Add a reusable `SoftTissueSurface` component bound to a `Mesh` and `SkinnedMesh`. Serialize settings, not live vertex positions. Bind once to the authored topology and invalidate/rebind when its authored geometry revision, skin, or skeleton changes.
2. Define the rest state as the authored, morph-adjusted mesh and the moving target as the **current skinned pose**. A neutral animation pose must produce zero secondary offset; after impacts the result returns to whatever pose animation currently specifies, without snapping to the bind pose.
3. Build surface adjacency once, respecting disconnected pieces and intentional seams. Use a separate per-vertex response mask and optional bone groups so the face, joints, rigid plates, and clothing can be excluded. Keep the eight existing joint/weight values per vertex unchanged.
4. Drive local strain from changes in the skinned target, such as rest-versus-posed edge length and joint bend, and drive impacts from mapped contact position, inward normal, impulse and barycentric seed. Normalize impulse by the number of fixed substeps, set a threshold, cap per-contact energy, and deduplicate persistent contacts so resting contact does not accumulate a growing dent.
5. Solve displacement relative to the moving target with an attachment spring, damping, and edge/area constraints. Use a fixed timestep; XPBD is a candidate because its compliance formulation reduces stiffness dependence on timestep and iteration count. A simple damped spring prototype is acceptable only if it passes the same stability and strain-limit tests. [XPBD paper](https://matthias-research.github.io/pages/publications/XPBD.pdf).
6. Expose maximum normal displacement and maximum tensile/compressive edge strain, with safe bounds and non-finite recovery. Limit total active vertices/contacts and skip simulation beyond a configurable distance or LOD. Bound propagation by mesh adjacency or surface distance; Euclidean radius alone can bleed through a nearby arm/torso or opposite sides of a thin mesh.
7. Keep runtime offsets in a transient buffer applied **after morph and skin** in mesh-local posed space, with CPU evaluation equivalent to the shader for mapped contacts, picking, portal cuts, and any collider mode that deliberately follows the deformed surface. Recompute normals/tangents or derivatives where offsets visibly alter the silhouette. Define whether the Bullet convex hull tracks the soft offset; default to stable bone-driven collision and use the soft layer as a visual/contact response unless a higher-cost collider mode is explicitly enabled.
8. Reset cleanly on scene restart, teleport/portal traversal, mesh edit, hot reload, skin rebind, and time discontinuity. No edit to `.mesh` occurs during playback. A save/reload cycle retains only component settings and authored geometry.

**Acceptance:** an elbow bend causes local compression without changing skin weights; a mapped impact causes a bounded dent on the contacted side and decays to the current animated pose; a steady resting contact does not pump energy; an unmapped contact produces no surface dent; animation, morphs, UVs, tangent space, portal cuts, and undoable mesh editing still work. Run at two physics step sizes and render on DX11, DX12, and Vulkan. Keep focused deterministic geometry/solver tests in `.local/tests` with a CMake source-existence guard.

## Optional: physical tissue layers and sliding skin

If the surface solver cannot provide the desired fat/muscle motion, add an authored low-resolution **inner driver** (muscle/fascia proxy) and an outer **skin shell**. Bind the high-resolution render mesh to the shell through barycentric/cage weights, keep bone weights on the authored render mesh, and simulate only the proxy. Required data would include thickness, attachment stiffness, tangential sliding limit, volume preservation, collision/self-contact, and rebind diagnostics. The skin shell must not cross the driver or snag at folds. Preserve source mesh topology and provide an explicit preview of inner driver, shell, binding error, and vertex displacement. Pixar's stable Neo-Hookean flesh work illustrates the fidelity and cost of volume-preserving tissue simulation; it is a reference for a later quality tier, not a requirement for the first real-time surface feature. [Pixar flesh simulation](https://graphics.pixar.com/library/StableElasticity/paper.pdf).

## Separate feature: subsurface scattering and layered skin material

1. Add material controls for SSS enable/weight, RGB scattering radius in scene units, scattering color, and optional thickness/transmission map. Exclude metallic and unlit materials by default; keep surface specular and fine normal detail sharp. Validate serialization and glTF/import fallback behavior.
2. For a real SSS effect, isolate the diffuse light contribution for marked materials, blur it with a depth/normal/material-aware profile, and recombine it with unblurred specular and emissive. A separable screen-space profile is a practical real-time first pass, but it needs tests for silhouettes, thin parts, overlapping characters, transparent materials, MSAA, shadow boundaries, and all three graphics backends. A wrapped-diffuse pixel-shader approximation can be a cheap preview but should be labeled as such, since it does not transport light between surface points. [Separable SSS paper](https://www.iryoku.com/separable-sss/); [original BSSRDF model](https://graphics.stanford.edu/papers/bssrdf/).
3. A layered **optical** skin preset can approximate surface oil/specular, epidermal pigment, and deeper hemoglobin-rich scattering with a small set of artist controls and precomputed diffusion profiles. This does not require three nested meshes. Use measured/validated color profiles where available and perform scattering in linear light. The two-layer spectral skin model demonstrates the separation between surface and subsurface terms. [Two-layer skin BSSRDF](https://graphics.ucsd.edu/~henrik/papers/skin_bssrdf/); [linear-light caution](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-24-importance-being-linear).
4. If an actual thin shell is used for geometry, do not count its thickness as SSS automatically. Thickness is a material/light-transport input; the physical shell is a simulation/render geometry input. Couple them only through an explicit authored thickness map or evaluated shell spacing.

**Acceptance:** SSS softens diffuse illumination and shadow transitions across the same skin surface without bleeding across silhouette or unrelated objects; specular highlights and pore normals remain crisp; RGB radius changes the visible scattering distance predictably; thin ears show controlled transmission; disabling SSS reproduces the current PBR result. Compare fixed-camera screenshots and GPU time at multiple resolutions and backends.

## Recommended order

1. Add post-physics scheduling, immutable authored/rest-state access, transient offset plumbing, and CPU/shader parity tests.
2. Implement pose-driven local strain and bounded impact response on the existing skinned surface.
3. Add editor masks, diagnostic overlays, performance budgets, and regression scenes.
4. Implement SSS as a separate material/render feature with linear-light validation.
5. Prototype a proxy flesh layer and sliding shell only if the simpler surface response fails the desired visual examples.
